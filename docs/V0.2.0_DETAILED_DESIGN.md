# 2. 設計判定

## 2.1 総合判定

**実装可能な粒度まで詳細化済み。**

次の2項目は`docs/PRODUCT_SPEC.md`へ記録済みの確定商品仕様である。

| ID   | 項目        | 確定内容         |
| ---- | --------- | ----------- |
| D-01 | 設定可能な通知時間 | 07:00〜23:00 |
| D-02 | 最終予約時刻    | 設定終了時刻の90分前 |

この2項目は実装前に`docs/PRODUCT_SPEC.md`へ明記され、Phase 1〜Phase 7の実装でも維持されている。

## 2.2 D-02の意味

利用者が次のように設定した場合、

```text
通知時間：08:00〜22:00
```

実際の通知予約範囲は次となる。

```text
予約開始：08:00
最終予約：20:30
```

Androidのinexact alarmは予定時刻より遅れて表示されることがあるため、終了時刻直前へ通知を予約しない。

これはv0.1.0で採用済みの08:00〜20:30という予約範囲を、利用者設定へ一般化したものである。現行スケジューラは開始08:00、終了20:30、1日2〜4件をコード内に固定している。

OSまたは端末メーカーによる大幅な遅延は完全には防止できないため、終了時刻はベストエフォートとする。

# 4. データモデル

## 4.1 NotificationWindow

### 配置

```text
lib/settings/notification_window.dart
```

### 責務

* 通知開始時刻を保持する
* 通知終了時刻を保持する
* 時刻設定の妥当性を保証する
* スケジューラへ分単位の値を渡す
* UI型である`TimeOfDay`へ依存しない

### 内部表現

0時からの経過分を`int`で保持する。

```text
07:00 = 420
08:00 = 480
20:30 = 1230
22:00 = 1320
23:00 = 1380
```

### クラス構成

```dart
final class NotificationWindow {
  const NotificationWindow._({
    required this.startMinute,
    required this.endMinute,
  });

  static const int stepMinutes = 30;
  static const int minimumDurationMinutes = 180;
  static const int earliestAllowedMinute = 420;
  static const int latestAllowedMinute = 1380;
  static const int deliverySafetyMarginMinutes = 90;

  static const NotificationWindow defaults = NotificationWindow._(
    startMinute: 480,
    endMinute: 1320,
  );

  final int startMinute;
  final int endMinute;

  int get durationMinutes;
  int get latestReservationMinute;

  static NotificationWindowValidation validate({
    required int startMinute,
    required int endMinute,
  });

  static NotificationWindow? tryCreate({
    required int startMinute,
    required int endMinute,
  });
}
```

### 算出値

```text
durationMinutes = endMinute - startMinute

latestReservationMinute =
endMinute - deliverySafetyMarginMinutes
```

### バリデーション順

1. 開始・終了が07:00〜23:00に含まれる
2. 開始・終了が30分単位
3. 開始と終了が同一でない
4. 開始が終了より前
5. 時間差が180分以上

### バリデーション結果

```dart
enum NotificationWindowValidationError {
  outOfRange,
  invalidStep,
  sameTime,
  startNotBeforeEnd,
  durationTooShort,
}

final class NotificationWindowValidation {
  const NotificationWindowValidation.valid(this.value)
      : error = null;

  const NotificationWindowValidation.invalid(this.error)
      : value = null;

  final NotificationWindow? value;
  final NotificationWindowValidationError? error;

  bool get isValid => value != null;
}
```

UIはこの結果をローカライズ文言へ変換する。

値オブジェクト内部へ日本語や英語のエラーメッセージを持たせない。

# 6. アプリ内一言選択

## 6.1 InAppMessageSelector

### 配置

```text
lib/content/in_app_message_selector.dart
```

### クラス

```dart
final class InAppMessageSelector {
  InAppMessageSelector({
    required List<MotherMessage> messages,
    required RandomSource random,
  }) : _messages = List.unmodifiable(messages),
       _random = random;

  final List<MotherMessage> _messages;
  final RandomSource _random;

  MotherMessage? select({
    required AppLanguage language,
    required MotherVoice voice,
    required String? previousMessageId,
  });
}
```

### 選択条件

候補は次のすべてを満たす。

```text
message.language == language
message.voice == voice
```

通知予約用の`ContentSelector`とは異なり、標準話者へのフォールバックを行わない。

現在の通知用Selectorは、指定話し方で候補がない場合に同じ言語の標準話者を使う。通知予約の既存挙動を守るため、このクラスは変更しない。

### 選択アルゴリズム

```text
完全一致候補を抽出
  ↓
previousMessageIdと異なる候補を抽出
  ↓
候補あり
  → ランダムに1件
  ↓
候補なし
  → previousMessageIdを含む完全一致候補から1件
  ↓
完全一致候補もなし
  → null
```

### 通知処理との乱数分離

`NotificationScheduler`と`InAppMessageSelector`には、別々の`RandomSource`インスタンスを渡す。

```dart
final schedulerRandom = DartRandomSource();
final inAppMessageRandom = DartRandomSource();
```

同じ乱数インスタンスを共有すると、アプリ内一言を選択した回数によって、通知時刻や通知内容の乱数列が変化する。

これは「アプリ内表示は通知予約へ影響しない」という要件に反するため禁止する。

## 9.6 通知時間変更

### 通知オフの場合

```text
updateNotificationWindow
  ↓
candidate = current.copyWith(notificationWindow: value)
  ↓
candidateを保存・再読込検証
  ↓
成功
  → state.settingsをcandidateへ更新
  ↓
失敗
  → 現在の設定を維持
  → settings_write_failed
```

通知は予約しない。

### 通知オンの場合

```text
処理中状態へ変更
  ↓
candidateを生成
  ↓
NotificationScheduler.rebuild(candidate)
  ↓
ScheduleSummaryをcandidateへ反映
  ↓
scheduleVersion=2
  ↓
保存・再読込検証
  ↓
成功
  → state更新
  ↓
失敗
  → 全通知取消
  → candidateをnotificationsEnabled=falseに変更
  → best effortで保存
  → failed状態
```

再構築失敗時も、利用者が選択した新しい時間設定は可能な限り保存する。

通知だけを安全側でオフへ倒す。

* 新しいアプリプロセスの起動
* オンボーディング完了
* 言語変更
* 話し方変更

現行アプリは`AppLifecycleState.resumed`で通知状態を確認しているが、このタイミングでは一言を変更しない。

## 9.10 一言ID保存失敗

一言自体は画面へ表示する。

```text

  ↓

  ↓
lastInAppMessageIdをbest effort保存
```

保存失敗時：

* 表示中の一言は消さない
* 通知をオフにしない
* `in_app_message_id_write_failed`を内部ログへ記録
* 次回起動時に同じ文章が選ばれる可能性を許容

通知設定保存失敗より低い重大度として扱う。

## 10.3 日次件数

```dart
int selectTargetDailyCount(
  NotificationFrequency frequency,
) {
  final width =
      frequency.maximumDailyCount -
      frequency.minimumDailyCount +

      _random.nextInt(width);
}
```

## 10.4 日次時刻生成

### シグネチャ

```dart
List<DateTime> generateTimesForDay({
  required DateTime date,
  required DateTime now,
  required bool isToday,
  required NotificationWindow window,
  required NotificationFrequency frequency,
});
```

### 開始分

```dart
var effectiveStartMinute = window.startMinute;

if (isToday) {
  final earliest = now.add(const Duration(minutes: 30));

  effectiveStartMinute = max(
    effectiveStartMinute,
    earliest.hour * 60 + earliest.minute,
  );
}
```

`now+30分`が別日になる場合は空配列を返す。

### 終了分

```dart
final effectiveEndMinute =
    window.latestReservationMinute;
```

### 容量

```dart
final capacity =
    ((effectiveEndMinute - effectiveStartMinute) ~/ 90) + 1;
```

次の場合は空配列を返す。

```text
effectiveStartMinute > effectiveEndMinute
capacity <= 0
```

### 件数

```dart
final desiredCount =
    selectTargetDailyCount(frequency);

final actualCount =
    min(desiredCount, capacity);
```

最低件数を配置できない場合も、件数を減らして続行する。

90分間隔を短縮しない。

---

## 10.5 ランダム配置

```dart
final requiredSpan =
    90 * (actualCount - 1);

final slack =
    effectiveEndMinute -
    effectiveStartMinute -
    requiredSpan;
```

各通知へ0〜`slack`のランダムなオフセットを割り当て、昇順へ並べる。

```dart
final offsets = List<int>.generate(
  actualCount,
  (_) => slack == 0
      ? 0
      : _random.nextInt(slack + 1),
)..sort();
```

通知時刻：

```dart
minute =
effectiveStartMinute +
offsets[index] +
90 * index;
```

通知設定は30分単位だが、実際の通知時刻は任意の分になり得る。
